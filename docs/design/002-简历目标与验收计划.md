# StudyPilot 简历目标与验收计划

确认日期：2026-09-08。本文合并已确认的核心链路计划与大纲/重点编排、切块实验细化计划；第一批核心能力与第二批 Anki、ASR 均纳入同一个 Goal。

本文是产品范围与技术设计对本次 Goal 的详细补充，定义目标契约和验收标准，不维护实时任务状态。唯一任务看板是 [PROGRESS.md](../../PROGRESS.md)。M0–M2 的历史验收不自动证明本次新增或调整的能力已通过。

## 1. Goal 与完成条件

将项目完善为可真实使用、可恢复、可评测的学习助手：用户导入课程资料与往年习题，生成有来源的课程大纲、重点与知识点计划，通过自然语言开展讲解、答疑、五题测验和三张复习卡生成；支持流式交互、跨知识点上下文管理、会话恢复、Anki 单向导出，以及音视频转写后进入同一知识库链路。

Goal 只有同时满足下列条件才可完成：

1. 本文 M3–M8 的能力已实现，通过适当的自动化检查、独立验收和真实依赖运行；失败能定位到步骤并恢复。
2. 真实课程资料通过生产后端 API 批量评测，核心学习链路通过后端 API 与前端操作验收，保存结果、持久化状态与 trace 证据。
3. RAG、上下文压缩、400 MB 上传形成可复现的对照报告，包含原始数据、配置、计算脚本、失败样本和结果限制。
4. Anki 实际导入可用；真实音视频完成转写、索引、检索与学习验证。
5. 当前设计、实现说明、任务看板与最终简历/面试说明一致；所有数字可回溯到实测数据。

不将编写计划、代码编译通过、离线 mock 测试或第一批完成视作整个 Goal 完成。不要求特定提升百分比，也不以“400 MB 从 20 s 到 9 s”为通过门槛；无提升的实验同样如实保留，简历按最终证据措辞。

## 2. 范围与约束

- 第一批支持 TXT/Markdown、可提取文本的 PDF、PPTX。保留文件、原文摘录与 chunk 引用，不建设页码/幻灯片定位界面、OCR、DOC/DOCX 解析。
- AgentScope Java 2.0.1 继续作为唯一 Runtime；Spring Boot 拥有业务状态、检索与持久化边界，不新增通用工作流引擎或学习多 Agent 系统。
- 保留知识点顺序状态机和一个活跃知识点；每点五题、三张卡。暂不增加跳过、任意切换、复杂重规划或考试时间分配优化器。
- 往年习题用于知识点重点判断，不建设独立题库产品，不把出现频次描述成未来考试概率。
- 第二批复习能力为 Anki 单向导出；不建设站内复习调度、Anki 成绩回流或“复习反馈自动调整计划”。简历不能声称这些未纳入的能力。
- 不建设注册/RBAC、知识图谱、长期用户画像、高级 checkpoint/replay、独立 trace 大屏或平台化 Runtime。
- 密钥只从受忽略的本地配置/环境读取，不进入 Git、trace、截图、研究打包或结果归档。用户原始课程资料不覆盖、不修改。
- 小样本先行。第一批模型调用上限为 2000 次，规划、摘要、失败和重试全部计入；embedding 请求及 token 另行记录。到限后保存可恢复状态并报告，不以重复调用突破规模约束或把未完成 Goal 标记完成。第二批按小片段/少量卡片试运行，再根据实测确定剩余调用规模。

## 3. M3：运行基础与测量契约

先校准密钥加载、后端端口与前端代理、依赖服务和模型配置，修复实际存在的配置问题。保存优化前的上传与上下文压缩基线，再替换实现。

模型初始选择为 DeepSeek flash 主链路、百炼 embedding；已讨论的模型 ID 为 `deepseek-v4-flash` 与 `qwen3.7-text-embedding`，embedding 初始维度 1024。实施前验证账户实际支持的 ID、接口、维度及 DOCUMENT/QUERY 参数契约，并冻结进运行清单；模型调用失败明确报错，不静默替换 provider。不同 embedding 模型/维度使用独立索引。

通过 traceId、runId 关联规划、模型调用、检索、工具调用、状态变化、压缩、失败和重试。记录真实 usage、耗时与错误；缓存输入是输入的子集，不重复相加，缺失 usage 不记为零。

每次正式实验保存 Git SHA、资料清单与哈希、模型和 prompt 版本、切块/检索/压缩配置、问题集版本、原始输出、trace 和统计脚本。测试资源与已有数据隔离；先跑一个 PDF、一个 PPTX、一个知识点的真实烟测，成功后扩大规模。

## 4. M4：资料处理、切块与 RAG

### 4.1 可靠资料流水线

上传提交后进入 RocketMQ：解析 → 规范文本 → 切块 → embedding → Elasticsearch。保存阶段状态、尝试次数、失败原因和执行权；支持重复消息幂等处理、进程重启后的过期执行恢复。

规范文本存 RustFS，chunk 与来源关系持久化，embedding 产物按内容哈希及模型/维度复用。失败从最早未完成阶段继续，只补未完成项；ES bulk 检查逐项结果，全部必要项成功后才标记已索引。Canal 补偿只重新入队，避免与 MQ 消费者各自执行整条流水线。空文本/解析失败返回明确状态，不包装成成功。

### 4.2 两种层级必须区分

- 教学层级：课程 → 章节 → 知识点，由资料覆盖与教学规划生成。
- 检索层级：文档 → parent → child，由确定性切块算法生成。

知识点通过来源引用关联多个 chunk，不强行与 parent 一一对应，不把模型生成的大纲冒充文档原始标题结构。

### 4.3 统一切块策略

优先保留可可靠提取的标题、段落、列表、代码和表格边界。相邻短段落合并成 parent，标题附着后续正文，不跨文档或可靠章节边界；超长内容先按段落/句子细分，最后使用 token 硬上限。PPTX/PDF 提取不可靠时按规范文本边界处理，不假定解析器总能提供标题。

parent 内划分 child，保留有界 overlap；真正较短的 parent 可以只有一个等长 child。parent 用于上下文回填，不参加向量召回；child 参与 BM25 和向量检索。父块去重并受统一上下文预算约束，保留实际命中的子块证据。

默认候选为 child 800、overlap 80、parent 最大 2400、parent overlap 0。所有大小使用固定版本 `jtokkit/CL100K_BASE` 的本地 token 计数；它是实验长度单位，不等同于供应商计费 token。配置必须真正接入算法，版本指纹包含算法、tokenizer 与参数；重建独立索引，不混用旧 chunk。

最多六组配置，顺序筛选，避免全因子实验：

| 步骤 | 配置 | 固定项与比较目的 |
|---|---|---|
| 1 | 固定 token 父子切块 800/80；结构优先 800/80 | parent 2400/0，比较结构打包贡献 |
| 2 | 结构优先 400/40、800/80、1200/120 | 中间组复用，比较 child 大小 |
| 3 | 所选 child 大小的 overlap 0%、10%、20% | 10% 组复用，仅新增两组 |

所有课程共享一套配置。仅在开发集上按“最差课程 Hit@5 → 课程宏平均 MRR@10 → 更低 embedding token”顺序选型，随后冻结；留出课程只验证迁移，不重新调参。报告长度分布、parent=child 比例、重复文本、索引开销和耗时，不声称参数普遍最优。

### 4.4 RAG 对照

提供调用同一生产检索服务的直接 API，可指定 BM25、VECTOR、RRF、父块回填与 topK。固定 embedding、候选规模和问题集，比较单路与 RRF 的 Hit@5、MRR@10 和延迟。

父块回填使用相同子块排名、相同上下文预算，单独比较证据覆盖、答案支持度、引用与上下文 token；它的收益不能计作子块排名提升。首批不增加 reranker 或 query rewrite。

## 5. M5：大纲、重点编排与对话学习

### 5.1 可恢复的规划阶段

1. 逐文档提取大纲，长文档按顺序分批处理后合并，覆盖选定课件，不能只靠一次 TopK 生成全课程大纲。
2. 合并同义与重复知识点，形成章节 → 知识点两层大纲；服务端分配稳定 ID，保存来源。
3. 将往年习题映射到既有知识点，标注建议重点、理由及习题依据。未匹配项保留待处理，不强行映射，不删除未被习题覆盖的基础知识点。
4. 根据学习目标产出有序知识点任务与估计时长；重点标注影响任务安排，但不做复杂优化器。

各阶段持久化输入指纹、输出、状态、错误、时间与 usage。未变化的上游结果复用，仅重试失败阶段；由明确的服务编排实现。校验 ID、结构、引用权限与范围，并以人工核对的样本检查语义支持。

“先大纲、再重点、再任务”归入简历第一条学习计划能力；面试展开阶段契约、覆盖策略、来源和重试，不另堆一条重复功能。

### 5.2 对话主导与服务端约束

统一自然语言消息入口，模型决定讲解、答疑及工具使用，移除业务入口预先指定 expectedTarget/强制 tool choice 的推进方式。服务端注入身份、知识库、当前知识点，验证相邻状态转换，并保留每轮最多一次转换规则；普通答疑不强制推进。

五题通过一次工具调用完整提交，整体校验后写入，提交答案前客户端不暴露正确答案。答案完整且映射明确时由服务端确定性评分；不完整或有歧义则澄清。三张卡片校验与持久化一次完成，失败重试不重复写入。

完成知识点前确保必要产物和上下文已持久化；失败保留可定位状态。MySQL 是业务状态最终依据，不能靠模型文本宣称完成。

### 5.3 上下文管理与恢复

完成知识点后仅摘要该点对话，保留目标、关键事实、错误理解及纠正、未解决问题和来源；避免每完成一个点就重复摘要所有历史摘要。保留阈值压缩以控制整体预算。

工具调用和结果成对保留，压缩放在回合末并设置幂等完成标识；压缩失败不伪装成功。完整前端聊天历史独立持久化；恢复模型上下文时加载摘要、近期消息和业务状态，不把全量聊天历史重新塞回模型，也不声称还原被摘要丢弃的原文。

## 6. M6：交互、上传优化与第一批正式验收

### 6.1 SSE 与核心前端

SSE 区分开始、文本增量、进度、已提交产物、最终结果与错误；不向界面发布半段测验 JSON。每会话一个活跃运行，requestId 去重；断线后查询原任务状态，避免重复发起操作。中断和恢复以最后持久化状态为边界，不承诺任意 token 重放。

在现有 React/Vite 上改进核心学习工作区：左侧课程计划、中间对话与测验卡片、来源抽屉。使用 Frontend Design Premium 维护 DESIGN.md 与共用交互规范；验收加载、空态、失败、窄屏、键盘、中文输入法和恢复，不扩展成全产品重做。通过真实前端操作检查关键链路。

### 6.2 上传与去重

保留优化前测量路径，再启用原生 S3 multipart；初始参数 8 MiB 分片、4 并发。持久化 uploadId 与 ETag，Redis Bitmap 记录完成分片，续传只补缺失部分；完成合并与服务端 SHA-256 校验后才建立可用文件/文档并入队。客户端计算哈希避免阻塞交互。

通过 `(userId, knowledgeBaseId, fileHash)` 唯一约束处理并发完成，返回已有文件/文档，不重复触发处理。迁移前检查现有冲突，不静默删除或合并用户数据。Bitmap 的贡献是进度/续传，性能收益区分并发传输与合并路径优化。

## 7. 数据与实验协议

资料根目录为 `D:\Download\BDNetdisk_DL`。优先操作系统 PPTX 与算法 PDF，各约六份；少量可读编译原理 PPTX 作为跨课程留出数据。最终以真实解析烟测和记录的清单为准，不为不可读样本引入 OCR 或特殊课程配置。

### 7.1 RAG 与规划

- 构建 100 道题：80 道可由资料回答、20 道证据不足；20 道开发集、80 道冻结测试集，测试集含未参与选型课程。
- 标签以文档哈希和原文证据摘录为基准，独立核对，不依赖某一版 chunk ID；测试题及标准答案不得进入评测知识库。
- 规划用往年习题与评测问题分开管理。检查大纲资料覆盖、重点理由有据、ID/来源合法、阶段失败可恢复。
- 使用后端 API 批量调用生产检索路径；证据不足题另报正确拒答及无依据回答情况，不能仅统计有答案题。

### 7.2 上下文压缩

两门主课程各固定一个五知识点任务，三种策略各重复三次，共 18 个会话：A 仅阈值压缩，B 当前知识点边界整段历史压缩，C 知识点局部摘要加阈值压缩。

冻结计划、用户脚本、模型、prompt、RAG 和阈值，交错执行各组。累计输入与总 token 均包含摘要和重试；同时检查关键事实保留、错误纠正、引用与任务完成。质量下降时不能只凭 token 降低声称优化成功。

### 7.3 上传与故障恢复

400 MB 样本记录精确字节数，每组五次，固定网络、客户端与服务端；分别比较串/并发、原有/原生合并路径，记录完整等待时间及传输、合并、校验分段耗时。性能组避免秒传/去重命中；续传另测重传字节，并发重复上传另测唯一文件/文档及处理任务。

对解析、embedding、索引失败，MQ 重复与消费者重启，学习状态/压缩持久化失败、SSE 断线开展针对性验证。可使用故障注入，但成功链路必须调用真实依赖；保留全部失败尝试，不能用 mock provider 冒充真实验收。

## 8. M7：Anki 单向导出

将已持久化复习卡导入实际 Anki。先验证可用的 AnkiConnect 接口与桌面环境，再实现最小字段映射、来源保留、导出状态与稳定去重标识；相同卡重复导出不重复创建笔记。

以实际 Anki 中可查看、可复习的卡片验收，并验证离线/失败后的明确提示与重试。不以生成导出请求或文件代替真实导入证据。不拉取复习记录、不修改学习计划。

## 9. M8：音视频 ASR 接入

使用下载目录中真实音视频的小片段先验证转写质量、调用方式和耗时，再选择有代表性的完整样本。实现前核实可用 ASR 方案及其认证、媒体限制和成本；现有 embedding/DeepSeek key 不自动代表某 ASR 服务已开通。

转写作为可恢复资料处理阶段，持久化音视频来源、转写结果、执行状态、错误和 usage/耗时，完成后复用 M4 的切块、embedding、索引和检索服务。未获得可用转写不能标记已索引。

验收真实音视频 → 转写 → 入库 → 有来源的检索 → 学习问答，并验证转写失败后重试不重复执行成功的下游阶段。不额外建设说话人识别、时间轴播放器或开放对象存储公网访问。

## 10. 执行顺序与交付物

顺序为 M3 → M4 → M5 → M6 → M7 → M8。M4 冻结 chunk/检索方案后运行正式 RAG 测试；M5 冻结压缩方案后开展正式会话实验；M6 汇总第一批结果，M7/M8 完成第二批真实链路。已有可复用代码以实际核验为准，不重复重写已满足契约的部分。

每个模块交付实现、必要迁移/配置、适当自动化检查、独立验收与真实运行证据；PROGRESS.md 记录下一步和证据路径。仅在失败、新修改或未解决风险需要时重复扩大测试。

最终交付包括可运行系统、可复现的评测脚本和版本化数据清单、三份指标报告（RAG/压缩/上传）、核心流程与恢复验收记录、Anki/ASR 验收记录，以及按实测结果改写的简历六条与关键面试机制说明。
