# 001 · 全局设计与范围

**日期** 2026-09-02 · **状态** AgentScope 换轴已确认；其余未决项逐项由用户拍板

## 1. 这份文档定什么

只定**边界**：做几个模块、每个模块拥有什么、不拥有什么、各做到多深。
不定实现。每个模块的内部设计各自另出文档（见 §9）。

判断一项内容该不该进来的标准：它是否服务于四个功能点之一，或服务于「运行时可控、可评测」这个主题。两者都不沾的一律进 §7。

## 2. 一句话定位

一个**可观测、可评测的学习垂类 Agent**：知识库进得来，学习流程跑得完，每一步看得见，改动好没好有数字。

不是通用 Agent 框架，也不再自研一套平行 Runtime。AgentScope 是目标态唯一的 Agent Runtime；StudyAgent 通过集成、策略、治理、业务映射与评测取得项目所需的可控性。

## 3. 模块清单

九个业务模块 + 五个共享层。

| 模块 | 大致内容 | 承载的技术点 | 分量 |
|---|---|---|---|
| `identity` | users 表、身份解析、**数据隔离的唯一强制点** | — | 薄 |
| `ingest` | 上传（分片/续传/去重）、对象存储、解析、清洗、分块、嵌入、索引、管道状态机、MQ、补偿同步 | 分块策略 | 大 |
| `rag` | 检索策略（BM25/向量/RRF/父子）、相关性阈值、查询改写、**以工具形式暴露** | RAG as tool、检索策略 | 中 |
| `agent` | AgentScope 集成与策略层：RuntimeContext、工具治理、context/记忆/checkpoint/trace 业务映射、子 agent 契约、prompt、codec | 框架能力验证、批量调用治理、context 压缩策略、文件记忆策略、checkpoint、轨迹、多 agent | 承重 |
| `learning` | 学习垂类流程：学习计划、知识点生命周期、讲解/答疑/测验/卡片各为一种 skill、知识点完成后 compact | 委派的使用方 | 中 |
| `review` | Anki 卡片、单向导出 / AnkiConnect adapter | — | 薄 |
| `profile` | 用户画像、长期记忆、轻量知识图谱 | 长期记忆 | 中 |
| `eval` | RAG 评测、轨迹评测、LLM as judge、黄金集 | RAG 评估、轨迹评测、judge | 承重 |
| 前端 | 知识库、学习会话、trace 时间线、画像 | — | 中 |

共享层：`config` / `common` / `model` / `mapper` / `algo`（以当前 `AGENTS.md` 的包结构约束为准）。

**承重的是 `agent` 与 `eval`**——差异化在这两块。`ingest`/`rag` 工程件可复用所以便宜。`identity`/`review` 刻意做薄。

## 4. 依赖方向

```text
identity  ←  所有模块（隔离条件）
ingest    →  rag        （供数据：索引）
agent     →  rag        （当工具用）
learning  →  agent      （跑在运行时上）
learning  →  profile     （产出学习信号）
review    ←  learning   （卡片来源）
eval      →  agent, rag （观察它们，不被它们依赖）
```

两条硬约束：

- **`agent` 不依赖 `learning`。** 运行时不认识「知识点」「测验」这些概念。这条一破，「通用运行时 + 垂类流程」的说法就不成立了。
- **`eval` 只被依赖方向的下游读取，不进请求路径。** 离线批量。

## 5. 各模块边界

### identity
拥有：`users` 表；从请求头 / API token 解析身份；隔离条件的单点注入。
不拥有：注册、登录、密码、找回、RBAC。（D-003）

### ingest
拥有：上传接口与分片/续传/去重、对象存储适配、格式解析、文本清洗、分块、嵌入调用、索引写入、管道状态机与失败可见性、MQ 投递、Canal 补偿。**含云端 API 形式的音视频 ASR。**
不拥有：检索。索引写入是它的终点，读是 `rag` 的事。
**注意**：工程件（分片续传/去重/S3/MQ/Canal）复用旧实现；分块与清洗**策略**重新设计（修正 D-002）。

### rag
拥有：检索策略与融合、相关性阈值、查询改写、结果装配与出处、以工具形式对 `agent` 暴露。
不拥有：索引构建、嵌入模型选型的落地（属 `ingest`）；评测（属 `eval`）。

### agent
拥有：AgentScope 与 Spring Boot 的集成、RuntimeContext 与业务身份绑定、Context/压缩/Memory/Session state/Trace 的项目级策略和业务映射、工具治理（体积上限/写入配额/超时/重试）、子 agent 任务契约、prompt 模板与版本、结构化输出 codec。
不拥有：通用 Agent Loop、消息存储、trace 事件采集等底层 Runtime 机制，也不拥有任何学习领域概念。AgentScope 2.0.1 已证实提供 `AgentState` / `AgentStateStore`，但未发现名为 `Checkpoint` 的公开 API；checkpoint fork/replay 是待运行 Spike 验证的产品目标，不能先写成框架已具备。框架能力不足时先形成证据，再由用户决定是否补建，禁止静默退回自研 Runtime。

**AgentScope 换轴说明**：早期按自建 Runtime 设计的 agent session/run/step/message/checkpoint 表、模块职责和相关 D-Q 选择已废弃，不作为兼容迁移目标。新 schema 只保留 StudyAgent 业务状态与经验证确有必要的映射数据；AgentScope 自有元数据按框架边界管理。详见 [ADR-0001](../adr/0001-agentscope-runtime-boundary.md)。

**2.0.1 API 边界**：`RuntimeContext` 绑定 `userId` / `sessionId`，workspace 由 `HarnessAgent.Builder.workspace(Path/String)` 配置；workspace 与默认 `${user.home}/.agentscope/state/<agentId>` JSON state store 相互独立。`AgentTraceMiddleware` 写 SLF4J，结构化 JSONL 需要显式 `JsonlTraceExporter`；`SessionTree` 日志不等同于完整产品 trace，也没有已证实的现成 traceId 查询 API。证据见 [Issue #67 Spike](../implementation/phase-0/agentscope-2.0.1-api-spike.md)。

### learning
拥有：学习计划的生成与推进、知识点生命周期、讲解/答疑/测验/卡片各自作为一种可委派的 skill、知识点完成后触发 compact、把信号投给 `profile`。
不拥有：Loop、压缩、trace 这些机制本身——它是使用方。

### review
拥有：卡片模型、单向导出到 Anki（AnkiConnect adapter）。
不拥有：调度。FSRS 暂不进主流程（D-005）。后续可能反向拉 Anki 统计，未定。

### profile
拥有：画像字段、长期记忆、**轻量实体-关系图谱**（从学过的知识点抽实体与前置关系，可视化即可）。
不拥有：图数据库、多跳推理。先出一版，再看是否优化。

### eval
拥有：RAG 检索评测（Recall@K 多策略对比）、答案质量评测（LLM as judge）、轨迹评测（工具选择/终止/绕圈）、人工标注黄金集与 judge 一致率校准、回归门槛。
不拥有：在线打分、请求路径内的任何逻辑。

### 前端
拥有：知识库管理、学习会话、**trace 时间线视图**、画像展示。
不拥有：编排配置、prompt 编辑等运营向功能。够用即可。

## 6. 六项深度档位（用户已定）

这六项每项都有「不做／中档／重做」三种可能，是范围失控的主要来源，所以单列。

| # | 项 | 定的档位 | 理由 |
|---|---|---|---|
| 1 | `agent` 与 `learning` 是否分开 | **分开** | `agent` 负责 AgentScope 集成、策略与治理，`learning` 负责垂类流程；不分会重新把框架机制和学习业务耦合在一起 |
| 2 | 音视频 ASR | **云端 API** | 本地 Whisper 要处理模型、显存、长音频切分，与主题无关且极易吃掉数周 |
| 3 | 知识图谱 | **轻量实体-关系** | 能支撑「前置知识回溯」这一个讲点即够；图库与多跳推理性价比低 |
| 4 | Trace 回放 | **时间线 UI + 从已验证的状态快照 fork 重跑** | 时间线满足功能点 3；AgentState 的恢复粒度与 fork 能力先做运行 Spike，不预设存在 checkpoint API |
| 5 | 多 agent | **仅扇出委派** | 多角色协商是另一个量级，且不服务任何功能点。judge 归 `eval`，不算协作拓扑 |
| 6 | 模块投入配比 | `agent`/`eval` 承重；`ingest`/`rag` 复用工程件重做策略；`identity`/`review` 薄；`profile` 先一版 | 把预算压在差异化的两块上 |

第 4 项留下一个待定：**重跑时工具结果复用记录还是重新执行**。

- 复用记录（确定性重放）：只换 prompt/模型，能干净证明改动生效。代价是工具结果需全量落库，体积大。
- 重新执行：真跑一遍，但索引可能已变，结果不可比。适合验证修复。

大概率两种都要，需定默认。另外**模型不确定性来源必须留存**：temperature、seed（provider 支持时）、模型版本——否则「重跑结果不同」无法区分改动生效与模型抖动。具体由 AgentScope Trace/AgentState 恢复能力 Spike 先确认框架边界，再交给用户决定；不沿用旧 D-Q 的自建表设计。

## 7. 明确不做

写进文档是为了防止范围蔓延。后续任何 agent 或讨论提出这些，直接引用本节拒绝。

- 注册 / 登录 / 密码 / 找回 / RBAC（D-003）
- 自建 FSRS 调度与复习 UI（D-005）
- 多租户
- Skill 市场、插件热加载
- 图形化流程编排
- Anki 双向同步（只单向导出）
- 真流式语音输入
- 多角色 agent 协商（Coach / Teacher / Critic 那类拓扑）
- 通用 Agent 框架化（不追求脱离本项目复用）

## 8. 简历与面试口径

**不要以「自研 Agent Runtime」领衔。**那句话邀请「和 LangGraph 比怎么样」这个必输的比较。

以可控与可评测领衔，例如：

> 学习垂类 Agent，重点在运行时的可控与可评测：基于 AgentScope 扩展点实施工具配额与结果体积治理；用可验证的 context 压缩策略支撑长会话；把框架导出的结构化轨迹映射为可查询的 traceId 时间线，并验证 AgentState 恢复与目标 checkpoint 的边界；检索策略 A/B（Recall@K）+ LLM-as-judge 答案质量回归。

选择 AgentScope 不等于放弃项目控制力。集成层必须用代码与测试回答下面四个问题；若框架扩展点无法回答，先形成 Spike 证据，再由用户决定补强范围。

1. 模型一次返回 200 张卡，服务端实际允许写几条？（工具治理）
2. 单次工具结果 2400 字进入上下文，第 8 轮 window 爆了怎么办？（context 策略）
3. run 在第 7 步崩了，`AgentStateStore` 能恢复哪些状态，能否支撑 checkpoint fork？（恢复边界）
4. 这次检索比上次好在哪，用哪个数字证明？（评测）

判断一条内容值不值得写：**能否被追问三层**。「怎么压缩的」→「分层，工具结果先降级为摘要，再丢历史轮次」→「为什么先降工具结果」→「占比最大，且原文可从 trace 回查」。

## 9. 后续详细设计文档顺序

顺序由依赖决定，不由兴趣决定。

1. **002 · AgentScope 能力 Spike 与集成边界**——用可运行代码确认 Loop、工具拦截、context、memory、AgentState 恢复、目标 checkpoint、trace、subagent 的真实扩展点，再定义项目级策略与业务映射；不设计平行 Runtime。
2. **003 · 表结构新 V1**——区分 StudyAgent 业务状态、必要映射数据与 AgentScope 自有元数据；旧 agent session/run/step/message/checkpoint 表不作为迁移目标。定完才能解锁 `model/` + `mapper/` 搬迁。
3. **004 · 记忆与画像**——文件记忆与数据库的分工、轻量图谱的形态。
4. **005 · 检索与分块策略**——分块参数、中文分词器、相关性阈值、查询改写与 ES 访问方式。
5. **006 · 评测**——judge 形态、黄金集、轨迹评测口径、回归门槛。
6. **007 · 学习流程与 skill 委派**——依赖 002 的实证边界。
7. **008 · ASR 摄入**——云端 API 选型与长音频切分。

Spring AI 的边界已澄清：现有 Chat/Tool 调用链只是换轴期间的迁移遗留，禁止新增消费者，待 AgentScope Harness、工具与学习流程迁移完成后删除；Spring AI Embedding 若暂留只属于 RAG provider adapter，其去留在 RAG 阶段单独决定，不构成第二套 Agent Runtime。旧 D-Q02/D-Q10 只保留历史背景，不作为答案。
