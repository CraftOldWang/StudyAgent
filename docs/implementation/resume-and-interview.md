# 简历表述与面试证据

这是2026-09-09的收尾草稿，不是Goal完成声明。真实五点学习、规划重点、SSE断线、持久恢复及媒体问答已有证据；正式压缩对照首轮发现工具参数歧义和摘要遗漏，修正复验中，尚无收益比例。原简历“20s→9s”不采用，替换为可复现数据；项目日期也应覆盖实际补充开发的月份。

## 六条目标表述

1. 基于AgentScope构建Plan-and-Execute学习流程，将资料归纳、大纲生成、习题重点标注与知识点任务分阶段持久化；以服务端状态校验约束讲解、五题测验和三卡生成，支持SSE讲解输出与Anki单向导出。
2. 基于Elasticsearch实现BM25与向量混合检索，采用RRF融合、子块检索与有预算的父块回填；在60道课程验证问题上，标注证据Hit@5相对BM25由70.0%提升至91.7%，支持来源追踪。
3. 实现知识点完成后的局部摘要与阈值压缩，保留目标、关键事实、错误纠正和来源；分别持久化业务状态、完整会话历史与模型上下文，支持中断后的会话恢复。**累计token收益待正式对照实验，不填写百分比。**
4. 通过traceId关联模型输入输出、工具执行、业务状态及usage，定位失败步骤与耗时；冻结18份课程资料和100道评测问题，开展检索对照与关键流程回归。
5. 基于RocketMQ解耦资料上传、解析/本地音视频转写、向量化与索引，通过阶段产物复用、执行租约和幂等写入恢复失败任务，减少重复处理；已验证索引故障及后端重启恢复。
6. 实现原生分片上传与断点续传，持久化uploadId/ETag并结合Redis Bitmap恢复进度，以SHA-256及唯一约束处理重复上传；本机400MB、4并发测试中，上传总耗时中位数由35.05s降至17.83s（每组5次）。

第1、3条须在当前版本真实学习验收通过后作为最终完成态表述。第4条的“回归”同时包含本地自动化和已有真实API记录，不能解读为所有自然学习流程已通过。Anki已实测单向导出，未实现复习记录回流或站内间隔调度，不能增加这两项描述。

## 关键追问与证据

| 追问 | 可解释机制与实测边界 |
|---|---|
| 为什么先大纲再重点？ | 逐文档遍历所有父块提取，再合并教学知识点；习题只能映射到已有点，保留课件/习题双向依据及未匹配项。候选短编号保证归组完整性，编号摘录避免模型抄错公式。真实v7识别两条有依据子问、保留十条未匹配内容；这是小规模开发验收，不是普遍准确率。 |
| 这算几个Agent？ | 规划是明确的服务阶段编排，学习执行用AgentScope ReAct工具循环；应用负责状态和提交。没有为了Plan-and-Execute名称建立多Agent团队。 |
| 重点如何影响计划？ | HIGH在估计基础时间上加10分钟，MEDIUM加5分钟；基础点保留。这是可解释的练习安排规则，不是考试押题概率。 |
| 教学层级与切块层级相同吗？ | 教学层级为章节→知识点；检索层级为文档→parent→child。知识点可关联多个来源，不能把模型大纲当作文档标题。 |
| chunk多大、为何不按课程调参？ | 六组开发对照后选择结构800/0、parent2400/0，使用固定jtokkit/CL100K_BASE计数；所有课程共用，编译原理作为未参与选型课程验证。800是本地长度单位，非供应商计费token。仓库常规默认仍为800/80，报告对应独立冻结配置，不能混称。 |
| RRF一定比向量好？ | 本组RRF和VECTOR同为55/60命中，RRF的MRR反而低于VECTOR；收益是相对BM25的42/60。中文问题配英文算法资料会影响BM25基线。 |
| 父块回填提升多少？ | 共享同一子块排名、正文预算4096时，子块证据命中55/60，父块54/60。父块补充局部上下文，也可能挤掉其它来源；不能声称本轮总体提升。 |
| 摘要如何恢复？ | 恢复摘要、近期消息及服务端业务状态；完整聊天历史另存用于界面。不是还原摘要丢失的原文。摘要按输入指纹缓存，部分成功可复用；工具调用与结果成对保留。 |
| token减少怎么测？ | 固定两门课程各五知识点，THRESHOLD/WHOLE_HISTORY/LOCAL各三次，18会话交错运行。计入摘要和失败重试，另核对事实、纠错、引用及任务完成；目前正式数据缺失。 |
| SSE断开是否取消任务？ | 只断开显示，后台回合继续；客户端按原requestId查询/恢复。当前只在NEW讲解阶段推送文本增量，其余阶段避免测验答案泄露先缓冲。真实text事件后断线、持久化原回合及重复请求去重已验证。 |
| 为什么不是全链路重试？ | 规范文本、chunk、embedding及ASR结果分别持久化，索引逐项确认；恢复定位最早未完成阶段。数据库执行令牌/租约控制提交权，未知usage不补零。无效媒体仍按既有MQ规则重投，不声称所有错误已分类为不可重试。 |
| Bitmap让上传快了多少？ | Bitmap记录进度，不能单独归因。整体优化包含原生对象存储合并、状态写入与事务调整、哈希缓冲；相同4并发中位数降低49.1%，是本机实现整体对照，非弱网或单机制消融。 |
| Anki丢响应后如何避免重复？ | 用稳定首字段定位既有笔记，重新查询后复用noteId；真实创建成功后丢响应、离线恢复及并发重试均验证。实现会复用既有笔记而不覆盖正文；手工编辑后重导场景未单独实测。 |
| ASR如何证明不是接口空壳？ | 完整797.838秒录音本地转写129.359秒；转写中终止后端后worker继续，租约恢复命中缓存，1次推理完成索引。真实MP4上传和来源检索也通过；没有人工逐字黄金集，不报ASR准确率。 |
