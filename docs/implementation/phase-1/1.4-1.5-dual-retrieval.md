## 范围

本批次只实现两个 Elasticsearch 单策略检索器及其共享最小命中对象，不包含 RRF、父块聚合、统一编排、消费者迁移或旧实现清理。

## 已执行选择

- `BM25Retriever` 使用 Elasticsearch Java API Client 的 `match(content)`，显式按 `_score` 降序并限制 `topK`。
- `VectorRetriever` 使用同一官方 client 的顶层 `knn` 搜索，字段为 `embedding`，`k` 和响应 `size` 均取本次 `topK`；`num_candidates` 使用 Elasticsearch 默认值。cosine 相似度由 `chunks-v1` 的 `dense_vector.similarity=cosine` mapping 决定，检索器不重复改写 mapping。
- 两路检索都只读取 `chunks-v1-read` 别名；公开检索参数要求服务端同时传入 `userId` 和 `knowledgeBaseId`，并在实际 ES 请求中分别以 `user_id`、`knowledge_base_id` 两个 term filter 强制隔离。两路还固定过滤 `chunk_type=CHILD`，确保召回结果可进入 child → parent 二跳。禁止默认用户、禁止由模型生成隔离参数，也不接受只校验而不进入查询的伪隔离。
- 共享 `RetrievalHit` 只保留后续融合与父块聚合当前需要的 `chunkId`、`parentChunkId`、`content`、原始分数和 `RetrievalStrategy` provenance。
- ES I/O 失败直接转成有明确策略上下文的 `BusinessException`，本批次不增加 fallback、重试或其他搜索后端抽象。

## 测试覆盖与验收

- BM25 请求使用读别名、`match(content)`、user/knowledge-base 双隔离 filter、`chunk_type=CHILD`、`_score desc` 和候选数量，并保留命中字段与 BM25 provenance。
- 向量请求使用 `embedding` kNN、user/knowledge-base 双隔离 filter、`chunk_type=CHILD`、配置维度和候选数量，并保留命中字段与 VECTOR provenance。
- 缺失用户或知识库 scope、向量维度不匹配时，在调用 Elasticsearch 前明确失败。

独立验收前静态审查曾发现两路召回缺少 `chunk_type=CHILD`；补入实际 ES filter 并增加精确请求断言后，#12-#16 retrieval 定向测试 14/14 PASS，`mvn compile` PASS，未参与实现的 subagent 独立验收判定通过。

Windows 全量测试的唯一 error 来自 Elasticsearch loopback 环境；后续 Linux 真实 Elasticsearch 8.15.3 已验证 #9-#11 的建索引、alias、mapping 与写入运行链。该结果排除了写链自身故障，但不扩张为 #12/#13 的真实检索集成验收。#12/#13 当前为“独立验收通过/待交付”。
