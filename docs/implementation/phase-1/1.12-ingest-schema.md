## 设计落实

- `file_records` 保留 `user_id + knowledge_base_id` 隔离键和设计指定的联合索引。
- `file_records.file_hash` 是完整文件字节的 64 位小写 SHA-256；上传预检在对象写入前按当前 user/KB scope 去重，不再保留 MD5 字段或双轨哈希语义。
- `documents` 使用单一 `pipeline_status` 和 `error_message` 表达长流程位置与失败信息，不沿用旧表的多个分散状态字段。
- `document_chunks.id` 是 `BIGINT` 主键；业务 `chunk_id` 和 `parent_chunk_id` 分别为 `VARCHAR(64)`，仅 `chunk_id` 唯一。
- `document_chunks` 只通过 `document_id` 关联 `documents`，不恢复 `user_id` 或 `knowledge_base_id` 冗余列；评测通过该关联从 V2 `Document` 确定 scope，ES `_id` 使用 `chunk_id`。
- 只建立设计明确给出的 `idx_user_kb`、`idx_status`、`idx_document`、`idx_parent` 与 `chunk_id` 唯一约束；不增加外键、级联、额外索引或未来字段。
- 三张表均显式使用 `InnoDB`、`utf8mb4`、`utf8mb4_0900_ai_ci`，与 V1 `users` 基线一致。
