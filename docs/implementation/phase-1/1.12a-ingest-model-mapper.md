# 阶段 1.12a：ingest 全局 model/mapper

- 对应任务：GitHub Issue #69。
- Scope：只新增与 V2 schema 一一对应的三组全局 model/mapper 和映射测试。
- 状态：V2 model/mapper 实现完成并纳入 Issue #19/#20 clean cutover；`mvn clean compile` 已通过，定向测试结果见文末验证状态。

## 实际变更

- 新增 `com.studyagent.model.FileRecord`、`Document`、`DocumentChunk`，仅包含 V2 表字段。
- `FileRecord.fileHash` 按 V2 约定承载完整文件 SHA-256；`Document` 使用 `fileRecordId`、`contentType`、`pipelineStatus`，不引入 `fileId`、`sourceType`、`parseStatus` 或 `indexStatus`。
- 主键 Java 类型统一为 `Long`，时间统一为 `LocalDateTime`；`pipeline_status`、`embedding_status` 与 `chunk_type` 直接映射为 `String`，不引入未由当前设计定义的枚举协议。
- 每个字段显式声明 `@TableId` 或 `@TableField` 列名，避免依赖全局驼峰配置推断。
- 新增全局 `FileRecordMapper`、`DocumentMapper`、`DocumentChunkMapper`，只继承对应 `BaseMapper`，不加入 V2 外列 SQL；全局 `com.studyagent.mapper` 已纳入 `MapperScan`。
- 映射测试通过反射核对表名、字段全集、Java 类型、显式列名及 Mapper 泛型绑定。

## Clean cutover 边界

本批已完成单一 V2 写入路径：全局 Mapper 注册并被上传、pipeline、知识库和评测消费者使用；`com.studyagent.modules.knowledge.infrastructure` 仍保留在扫描范围，仅提供当前仍在用的 `KnowledgeBaseMapper`。旧三实体和三 Mapper 已删除，不引入双写、适配层或双 Mapper 注册。
