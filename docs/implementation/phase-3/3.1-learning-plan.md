# Phase 3 / 3.1 学习计划生成实现记录

- 状态：已纳入 M2 纵向闭环，待 M2 完整批次验收
- 范围：输入非空学习目标，单次调用当前 AgentScope DeepSeek `Model`，严格解析学习计划 JSON 数组为三字段 DTO，并由学习持久化服务创建会话和有序知识点。

## 实现选择

- `LearningPlanService` 位于 `com.studyagent.learning`，与当前子域包结构一致；返回 `List<LearningPlanItem>`。
- 服务通过 `@Qualifier("agentScopePrimaryModel")` 注入现有 AgentScope `Model` Bean。该 Bean 由 `deepseek:deepseek-chat` provider 解析为 AgentScope `OpenAIChatModel`，并由 `DeepSeekFormatter` 负责 DeepSeek OpenAI-compatible 消息格式；服务不创建第二个模型，也不接入旧 Spring AI `ChatModel`。
- 计划生成直接调用 `Model.stream(List<Msg>, List<ToolSchema>, GenerateOptions)` 一次，禁用流式结果后聚合文本；计划本身不需要工具或 Agent loop。生成结果由 `LearningPersistenceService` 在一个事务内保存。
- prompt 要求只返回 JSON 数组，并要求通常拆为 3-5 个知识点；解析器只接受纯 JSON 数组，不从 Markdown 或解释文本中截取 JSON。

## 输出契约与失败处理

每个元素必须恰好包含以下三个字段，DTO 也只有这三个字段：

```json
[{"topic":"Java 面向对象","subtopics":["封装","继承"],"estimatedMinutes":45}]
```

- `topic` 必须是非空字符串；`subtopics` 必须是字符串数组，数组元素必须为非空字符串；`estimatedMinutes` 必须是可转为 `int` 的正整数。
- 空目标、模型异常、空模型响应、非数组、尾随 JSON 内容、Markdown 围栏、未知字段和字段类型不符均抛出带明确原因的 `BusinessException`。
- 模型错误只转换为明确失败，不在服务内 fallback、重试或静默修复；不写入 `learning_plan` 表。

## 验证

`LearningPlanServiceTest` 使用 Mockito mock AgentScope `Model`，覆盖成功映射、非空目标校验、模型失败单次调用、非数组/非法正整数、Markdown 与未知字段拒绝；mock 不发起远端请求。

定向命令：

```text
mvn -Dtest=LearningPlanServiceTest test
mvn -DskipTests compile
```

`LearningPlanServiceTest` 已纳入当前可编译的 M2 测试集；最终全量命令与真实 smoke 结果记录在 M2 批次交付中。

## 不在范围内

计划生成仍不使用工具、fallback/retry、学习 subagent 或旧 Spring AI Chat/Tool 链路；这些边界不影响后续由 M2 服务承接持久化和学习流程。
