# 3.2 KnowledgePointLifecycle 实现记录

M2 使用最小显式状态集合：

```text
NEW → EXPLAINING → QUIZZING → CARD_GENERATING → COMPLETED
```

`KnowledgePointStatus` 与 `KnowledgePointLifecycle` 只负责枚举转换和相邻推进校验，不引入状态机框架。
`LearningPersistenceService` 在事务内写入状态、时间与错误；模型只能通过服务端
`learning_state_transition` 工具提交目标状态，整个 Agent turn 成功且业务产物通过校验后才真正提交数据库状态。

失败只写当前 session/point 的 `errorMessage`，不推进状态。`QUIZZING` 中答疑只调用模型并清除旧错误，
不会退回 `EXPLAINING`。完成当前知识点后按 `sequenceNo` 激活下一 `NEW` 点；最后一个完成后 session 才成为 `COMPLETED`。

单元测试覆盖全部四个合法相邻推进、跳跃/重复/回退/终态拒绝，以及 Agent 工具目标与服务端预期不一致时拒绝。
