# Phase 3 / 3.7 Context compaction

生产 `HarnessAgent` 保留常规消息阈值压缩（trigger 6、keep 2）。M2 另外在每个知识点完成 turn 的明确边界调用
公开 `ConversationCompactor.compactIfNeeded(...)`，不使用反射或私有 API。

一次性完成契约固定为：

- `triggerMessages(1)`、`keepMessages(1)`；
- summary prompt 必须保留 AgentScope 要求的 `{messages}`；
- `compactIfNeeded` 的 `Optional` 为空视为失败，不推进 `COMPLETED`；
- 结果替换同一个 `AgentState.contextMutable()`，随后调用 delegate `saveAgentState(context)`；
- compaction 成功后才在 MySQL 提交知识点完成并激活下一点。

`LearningContextCompactorTest` 使用本地 recording model 验证真实 AgentState 被替换并保存；
`LearningFlowServiceTest` 验证 compaction 失败时状态停在 `CARD_GENERATING`，已持久化的三张卡可在重试时复用，避免重复生成。
