# 0.7 users 新 V1 迁移基线

## Scope

- 用 `V1__create_users.sql` 取代 AgentScope 换轴前的 V1-V7 迁移历史。
- 新 V1 仅创建 identity 子域拥有的 `users` 表并插入初始用户。
- 本任务不创建其他业务表，不新增实体、Mapper 或 identity 接线，也不修改应用配置。

## 用户决策

- 初始用户固定为 `id=1`、`username='default-user'`。推荐依据：当前阶段不做登录与 RBAC，`default-user` 是与既定 `user_id=1` 验收相匹配的确定性占位身份。取舍：它不承担真实身份语义，未来身份系统接入不在本任务 scope 内。
- `users` 表显式使用 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci`。推荐依据：显式声明可确保新基线跨环境使用一致的事务引擎、完整 Unicode/中文字符集与排序规则。取舍：该 V1 明确面向 MySQL 8.1，不承诺兼容其他数据库或旧版 MySQL。
- 两项选择均已由一次性 MySQL 8.1 容器中的真实 Flyway 迁移测试验证，执行结果见“验证证据”。

## 迁移重建影响

旧 V1-V7 属于换轴前 schema，不作为兼容迁移目标。本次直接重建 Flyway V1 基线，因此只适用于全新的数据库；已经应用旧迁移历史的开发库不能通过追加迁移原地升级，应删除并重建该开发库后再启动应用。不得对需保留数据的数据库执行 `flyway clean` 或 `repair`。

## 集成测试

`UserSchemaMigrationIntegrationTest` 默认在未提供 JDBC URL 时跳过。实际验证必须显式指向一次性 MySQL 8.1 数据库：

```powershell
$env:STUDYAGENT_MIGRATION_TEST_JDBC_URL = 'jdbc:mysql://127.0.0.1:<port>/study_agent_v1_test'
$env:STUDYAGENT_MIGRATION_TEST_USERNAME = 'root'
$env:STUDYAGENT_MIGRATION_TEST_PASSWORD = '<temporary-password>'
mvn '-Dtest=UserSchemaMigrationIntegrationTest' test
```

也可改用对应的 `studyagent.migration-test.jdbc-url`、`studyagent.migration-test.username`、`studyagent.migration-test.password` JVM system property。测试会执行 Flyway 并验证：

- 数据库仅有 `users` 与 `flyway_schema_history` 两张表，旧业务表不存在。
- `users` 四列的类型与非空约束、username 唯一索引正确。
- 表引擎、字符集与排序规则符合用户决策。
- 初始用户和 Flyway V1 历史正确。
