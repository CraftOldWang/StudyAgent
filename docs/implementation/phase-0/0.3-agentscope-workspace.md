# Phase 0 / 0.3 AgentScope workspace 本地文件系统配置

- 关联任务：Issue #3
- 状态：实现完成，待独立验收
- 范围：只配置 AgentScope workspace 路径及启动时目录创建，为 0.2 的 `HarnessAgent` Bean 提供路径依赖。

## 选择与依据

- 配置属性使用 `study-agent.agentscope.workspace`，类型直接绑定为 `Path`。它位于现有 `study-agent` 配置命名空间内，且不额外引入字符串到路径的转换层。
- 默认值为 `${AGENTSCOPE_WORKSPACE:${user.dir}/.agentscope/workspace}`。环境变量可覆盖本地默认值，默认路径与 AgentScope 2.0.1 的框架默认一致，也避免把不会自动展开的 `~` 传给 Builder。
- 应用启动时显式调用 `Files.createDirectories(...)`。AgentScope 2.0.1 的 `WorkspaceManager.validate()` 在目录不存在时只告警，不能承担目录初始化。
- 暴露名为 `agentScopeWorkspacePath` 的 `Path` Bean。`Path` 是通用类型，后续 0.2 应通过 `@Qualifier("agentScopeWorkspacePath")` 注入，避免与其他文件路径 Bean 产生类型歧义；本任务不为此增加自定义封装层。
- workspace 与默认 `${user.home}/.agentscope/state/<agentId>` state store 继续分离。本任务没有决定 state store 改址或同盘策略。

## 配置与覆盖

```yaml
study-agent:
  agentscope:
    workspace: ${AGENTSCOPE_WORKSPACE:${user.dir}/.agentscope/workspace}
```

本地默认目录是当前进程工作目录下的 `.agentscope/workspace`；设置 `AGENTSCOPE_WORKSPACE` 后使用覆盖路径。测试只使用 JUnit 临时目录，不会在仓库生成 `.agentscope`。

## 验证

`AgentScopeWorkspaceConfigurationTest` 验证：

1. 外部属性可直接绑定为 `Path`；
2. 覆盖路径不存在时会被创建；
3. 命名 Bean 返回该路径，创建后确实是目录；
4. `HarnessAgent.builder().workspace(path)` 接受该路径，不要求在本任务构造 Model 或 Agent。

## 非本任务范围

- 不创建 `HarnessAgent` Bean，不选择 Model、provider、fallback 或重试参数；
- 不调整 Spring AI；
- 不迁移或同盘管理 AgentStateStore；
- 不处理跨进程锁、PVC、分布式 workspace；
- 不增加 Controller，也不实现阶段 0.8；
- 不修改其他 `application.yml` 已知问题或新增依赖。
