# M5 可恢复学习规划

本模块落实目标契约 5.1：资料覆盖、教学大纲、习题重点和顺序任务。它是学习计划内部的阶段编排，仍使用 AgentScope 模型、Spring Boot 服务和 MySQL，不引入通用工作流引擎。

## API 与持久化

先 `POST /api/learning/plans` 提交 `knowledgeBaseId`、`learningGoal`、`lessonDocumentIds`、`exerciseDocumentIds` 和可选 `targetPointCount`。创建操作只校验并保存资料快照，返回可恢复的 run ID；未指定课件时使用知识库中已索引且未被选为习题的文档。习题与课件不能重复选择。

`POST /api/learning/plans/{id}/execute` 执行或恢复，`GET` 同一路径查询阶段和结果。`POST /api/learning/plans/{id}/session` 将成功任务转换成学习会话，在事务中锁住规划记录；重复或并发请求返回已有会话，知识点沿用大纲阶段分配的稳定 Long ID。

V10 新增 run 和 stage-attempt 表，保留每次尝试的输入指纹、原始输出、解析产物、usage、traceId、状态、错误及耗时。run 的执行令牌与 600 秒租约控制提交权；模型请求在数据库事务外进行，每个阶段开始和结束都检查并续租。过期运行可由同一 execute API 恢复。第一版没有规划后台自动重跑扫描器。

成功阶段输入指纹不变时直接复用。已成功阶段的资料、prompt 或模型配置变化时明确拒绝混用，要求创建新任务；失败阶段可使用修正后的契约重新尝试，每次保存新的输入指纹，上游成功结果继续复用。失败尝试保留，不覆盖为后续成功结果；进程中断导致缺少终态 usage 时仍记为未知，不补零。usage 原始账本以各阶段 traceId 关联实际 provider 尝试。

## 阶段契约

1. `EXTRACT/n`：按选定文档顺序读取所有 PARENT，按正文 4800 个本地 token 打包，不跨文档。没有 TopK 筛掉整份课件。每个来源都需有知识点或未提取说明；同一父块允许正文和图片占位说明并存。提取短原文依据并校验摘录确实存在。
2. `OUTLINE`：合并相近子主题与同义点为章节→知识点，必须消费全部候选 ID，每个候选只归属一次。来源和已校验摘录由服务端合并，不让模型伪造关系。模型先输出最终知识点列表，服务端按 chapterTitle 分组并分配章节、知识点 Long ID；用户指定数量时检查列表总数，避免嵌套章节掩盖数量超标。
3. `EMPHASIS/n`：逐批读取习题，映射到已存在知识点。每个匹配同时包含习题原文与该知识点已经确认的课件摘录；引用的存在性和归属可确定性检查，语义相关性仍需抽查。没有具体对应依据时保留 unmatched，不能仅凭“大体属于同一课程”强行关联。不是独立题库，也不把习题答案当作已验证事实。
4. `TASKS`：所有大纲知识点恰好出现一次，生成先修概念在前的顺序及基础时间。HIGH 在模型基础时间上追加 10 分钟，MEDIUM 追加 5 分钟，NORMAL 不追加；这是一条可解释的练习时间规则，不是考试概率估计或优化器。没有习题时重点为空，基础点照常保留。

单次模型输入上限 28000 本地 token、输出上限 6000 token；超限保留已完成阶段并明确失败，不截断资料或静默少读。重点判断复用短摘录，避免重复送入整门课程全文。参数统一放在 `LearningPlanningProperties`，当前没有逐课程配置。

## 已发现的问题与验收边界

首次真实规划使用两份编译原理 PPTX 和两页习题 PDF，清单为 `eval/planning/corpus-v1.json`。五个实际模型调用完成规划；重复 execute 没有增加调用，两个并发 session 请求返回同一会话。原始 run `2097419430076522497`、会话 `2097419870356807681`，HTTP 保留在 `.eval/runs/m5-planning-smoke-v1/`。

该版只在 prompt 中表达“五个知识点”，实际输出十个；部分重点泛泛关联“编译器基本概念”，因此不作为最终质量验收。v2 增加显式数量约束、知识点短摘录和习题/课件双向依据。另一个真实失败暴露了正文与图片占位同父块的情况，原互斥分类校验已修正；失败尝试仍保留在 run `2097422040987742209`。

可复现入口为 `scripts/run-planning-smoke.py`，进程中断注入入口为 `scripts/verify-planning-recovery.py`。v2 已验证失败阶段恢复与成功提取复用，但重点语义仍不合格、TASKS 因代码围栏失败，详见 `docs/evidence/m5/planning-development-review.json`。当前 v3 使用 [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 的 `json_object` 模式并强化直接依据规则；13 项定向回归与独立打包通过。

v3 真实模型测试被自动审批拒绝，两次复核均要求用户明确确认课程内容发送至 DeepSeek。现有用户已授权资料测试和 provider 使用，但工具审批未接受该授权范围；未通过其它命令、工具或 provider 绕过。v3 尚无真实模型验收，进程中断注入未成功实施，不能声称规划进程恢复已实测。待审批问题解决后从 `.eval/runs/m5-planning-smoke-v3/` 创建新版本任务验收。自然对话、摘要策略、SSE 与前端改进是 M5/M6 的后续工作，当前规划接口通过不代表整个 M5 完成。
