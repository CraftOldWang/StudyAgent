本轮未调用embedding、未写入索引。使用此前本地XML提取的幻灯片文本（去除导出器插入的页码标题），执行项目 `StructuredChunker`、`TokenWindowChunker` 和 `JtokkitTokenCounter`。正文合计116,431个CL100K_BASE token。

百炼北京地域 `qwen3.7-text-embedding` 同步单价为0.0005元/千输入token，即0.5元/百万token；最多20条输入/请求。异步Batch价格为0.00025元/千输入token，不是同步请求传20条就自动享受折扣。

按本地token代估账单，单组约0.058–0.070元，五组不复用约0.319元、复用约0.273元。实际Qwen token数、地域、重试与可用免费额度会改变账单；未查询账号余额或免费额度。以上不含DeepSeek回答/摘要、OCR、云基础设施费用。

检索问题的embedding另计。BM25不需要query向量；当前search API每次VECTOR/RRF请求会调用一次query embedding，因此五配置×60题×两种模式为600次查询向量请求。若以后批测显式复用相同问题的向量，60个向量即可覆盖所有配置；当前接口没有这种跨请求复用。

## 建议实验顺序

1. 父块2400、模型及维度、检索候选数保持一致。用400/40、800/80、1200/120比较子块大小（固定10% overlap）；用800/0、800/80、800/160比较重叠比例。共五组，不需要九组全排列。
2. 子块选参先使用相同检索方法，避免把切块和融合同时改变。参数确定后，再对比BM25/VECTOR/RRF。
3. 父块对照复用同一次子块排名、固定正文预算，比较证据是否完整；不把父块收益混成Hit@5提升。
4. 60题可分20题选参、40题最终比较，两部分各保持关键词/语义比例。最终独立报告分母为40；若60题全部调参，则只报告为开发/诊断集，不声称独立测试效果。
5. 记录命中率、首个有效证据排名、上下文完整性、重复内容与token成本。公式/表格未被解析的情况单独处理。
