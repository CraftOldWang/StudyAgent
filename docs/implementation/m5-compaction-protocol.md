## 先行验证与版本边界

formal-v1于2026-09-09开始，首会话第四点出题因连续提交选项字母而失败，未运行后续17会话；54次尝试与完整失败记录保留，见`docs/evidence/m5/formal-v1-gate-review.json`。第三点回忆保留了标记、误区和纠正结论，未保留待解决问题。首点后实际后端重启及第二点模型输入加载持久摘要验证通过：1条原摘要加本轮用户消息，并未恢复全量聊天历史。

formal-v2将沿用相同两份计划、用户脚本和参数，使用新的18个初始会话。全策略统一采用`learning-compaction-v2`摘要提示：先保留用户误区/标记和未解决问题，再概括课程内容；预算仍为700。测验工具明确correctAnswer必须复制完整选项文本。v1数据单列为失败的先行验证，不能混入v2对照或计算收益。

v1另遇只读导出器的Unicode分行问题：JSON字符串中的U+2028被splitlines()误当记录边界。仅改为按物理LF分行，原始SQL输出和脚本前后哈希保留于export-amendment.json；该观察性修订不改变模型输入或样本。v2从开始即冻结修正后的导出器。

## 固定任务与执行

- 算法、操作系统各使用六份已经真实入库的课程资料，清单`eval/planning/compression-corpus-v1.json`；检索使用`eval/rag/config-validation-selected.json`，复用已有索引，不将答案或评测脚本写入知识库。
- 每门课程由真实规划API生成一个五知识点任务，检查覆盖与顺序后冻结。每份计划建立九个独立NEW状态副本：THRESHOLD、WHOLE_HISTORY、LOCAL各重复三次。只复制初始任务，不复制对话、测验、卡片或摘要。
- 每个知识点固定讲解、五题测验、提交五个A答案、生成三卡四步；第1、3、5点另有追问，共23回合。第1点给出一个明确的错误理解、个人标记和暂不解答的问题，第3、5点检查原标记、原误区、正确结论及未解决问题四项回忆。全功能试跑已单独验证每点不完整答案澄清，本实验不重复该步骤。
- 三组使用完全相同的用户文本；按重复轮换策略顺序并交错课程。第一次SSE都在实际文本到达后断开，后续查询原请求；重放已完成requestId必须返回相同回合与attemptCount。
- `run-compaction-experiment.py --prepare-only`冻结计划、脚本、执行器、证据导出器、JAR和检索配置哈希。正式运行中禁止修改这些文件或混入另一索引。默认先执行两个会话检查，再扩至18个。
- 在第一个正式会话完成首知识点后，记录停机时无活跃请求，重启同一配置的后端，再继续剩余四点；检查实际模型输入加载持久摘要/近期消息，而不是恢复全部聊天记录。

## 用量口径

学习使用`deepseek-v4-flash`非推理模式，temperature=0；阈值8000本地估算token、摘要输出上限700、学习回复上限3000、每回合最多5次Agent迭代。规划模型配置不参与学习策略比较。

从持久调用账本按sessionId、turnId关联LEARNING和COMPACTION，累计全部实际provider尝试，包括失败、摘要及重试。缓存输入包含在输入token中，不重复相加。缺失usage显示未知，不补零；不能将有未知用量的组记为完整精确结果。

报告每个会话及每个课程/策略的累计输入、输出、总token、调用数、摘要数和完成情况，给出三重复的中位数与范围。相对A的变化按`(A-C)/A`计算，并分别列出两课程结果；B作为整段历史摘要的对照。失败会话不得从分母中删除。时间仅作观测值，不视作严格延迟基准。

## 质量与证据

1. 所有要求的回合必须成功、五点完成、每点五题三卡；客户端提交前不可见答案，重复请求不新增模型调用或产物。
2. 第1点纠正必须符合课件证据，并保留暂不解答的问题。第3/5点分别检查：个人标记是否保留，是否正确回忆原误区，是否给出正确结论，是否保留未解决问题。不存在的记忆不得猜造。固定标记是会话记忆探针，不是课程知识，也不会进入RAG索引。
3. 回忆题只问先前记录，不重复提供标准答案。质量规则和对应课件证据在开始前冻结；关键词检查只供筛选，最终保留原始回答并逐条复核语义与否定关系。
4. 校验资料来源归属与可打开性；保留关键讲解、测验及卡片的真实API输出和抽查记录。结构检查不等同于教学内容完全正确，更不证明学习效果。
5. 导出实际模型输入/输出、工具执行、状态变化、摘要和最终上下文；保存原始结果、配置、代码版本及哈希。SQL只读取这些持久产物，不代替生产API执行学习。
