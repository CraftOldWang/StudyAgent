# 阶段 2.6：review 与 learning 表迁移

- 对应任务：执行方案 2.6。
- Scope：只新增 `learning_sessions`、`learning_plan`、`knowledge_points`、`review_cards` 四张表及迁移集成测试；不创建实体、Mapper、service 或 tool。
- 状态：实现完成，等待 Phase 2 当前完整批次统一编译、测试和独立验收。

## 设计落实

- learning 表严格使用当前技术设计的业务字段：学习会话保存 `agentscope_session_id` 映射，计划保存 `plan_json`，知识点保存生命周期状态与起止时间。
- `learning_sessions.knowledge_base_id` 是单知识库会话 scope；当前有效 KB 以当前用户在 `documents` 中存在匹配 `(user_id, knowledge_base_id)` 为准，不新增 `knowledge_bases` 表。
- review 只保存卡片及单向 Anki 导出状态，不加入 FSRS 调度字段。
- 四张表的主键均为 `BIGINT`，时间均为 `DATETIME`；只建立设计明确给出的 `idx_user`、`idx_as_session`、`idx_session`、`idx_session_status` 与 `idx_kp`。
- 不增加外键、级联、触发器、审计列或未设计索引，避免提前引入兼容和生命周期决策。
- 四张表均显式使用 `InnoDB`、`utf8mb4`、`utf8mb4_0900_ai_ci`，与 V1/V2 基线一致。

## 兼容核对

- V1 只创建 `users`，V2 只创建 `file_records`、`documents`、`document_chunks`；不存在同名表或字段覆盖。
- 仓库仍有换轴前 `ReviewCard` Java 类型，但旧 agent/runtime schema 已明确不作为新 Flyway 基线的兼容迁移目标，本任务不修改旧消费者。
- V3 加入后，V1/V2 的迁移测试改为只断言各自负责的表和 history 记录；V3 使用独立测试覆盖四张新表。
- 2.7 fixture 通过 V2 `documents` 提供 scope，并关联来源 `document_chunks`；不在 chunk 表恢复 user/KB 冗余字段，也不为多库会话准备数据。
