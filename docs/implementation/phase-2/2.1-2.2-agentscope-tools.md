# Phase 2.1-2.2 AgentScope tools

状态：实现完成，等待当前 Phase 2 批次的独立验收。

## 调用范围

`AgentInvocationScope` 是服务端绑定的 typed scope，携带 `userId`、`knowledgeBaseId`，以及写卡所需的 `knowledgePointId`。`AgentInvocationScopeFactory` 只接受服务端传入的 ID，并以 `documents(user_id, knowledge_base_id)` 的存在性验证知识库归属；模型输入不承载这些权限字段。

## 2.1 knowledge_search

工具的模型参数严格为 `{query}`。工具从 `RuntimeContext` 取得已验证的 scope，通过现有单库 `RetrievalService` 执行 BM25 检索，并由 `KnowledgeSearchRetryExecutor` 包住调用。检索请求的 user、knowledge base、candidate limit 和 topK 全部由服务端绑定或配置提供，返回结果只包含检索命中所需的 chunk 内容与分数。

## 2.2 review_card_write

工具的模型参数严格为 `{drafts: [{front, back, sourceChunkId}]}`。写卡服务从 `DocumentChunk` 解析对应 `Document`，验证 source chunk 与 scope 的 user/knowledge base 一致后，使用全局 V3 `ReviewCardMapper` 在一个事务中批量写入。user、knowledge point、knowledge base、导出状态和创建时间均由服务端写入；不存在默认用户回退。

## AgentScope 注册与治理

`AgentScopeAgentConfiguration` 创建 `Toolkit`，自动注册 Spring 容器中的 `AgentTool`，并将同一 toolkit 注入现有 `HarnessAgent`。已有 `ToolGovernanceInterceptor` 继续在 AgentScope 调用链中将 `review_card_write` 的 drafts 截断到最多 5 张，工具本身不重复实现该治理规则。

## 测试

新增测试覆盖 scope 的 documents 归属验证、query-only 和 drafts-only schema、服务端 scope 绑定、检索重试调用、source chunk 跨 scope 拒绝、V3 批量写入事务声明，以及 AgentScope toolkit 注册。
