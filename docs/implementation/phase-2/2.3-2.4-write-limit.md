# Phase 2 / 2.3-2.4 `review_card_write` 单次写入上限

## 范围

- 只治理 AgentScope 工具 `review_card_write` 的单次草稿数量。
- 当参数 `drafts` 超过 5 项时，工具实际收到前 5 项，并记录一条 WARN 日志。
- 其他工具不受此条数规则影响。
- 本批次不实现工具、重试、trace、持久化配额、配置化或通用治理框架。

## AgentScope 2.0.1 扩展点依据

本机 2.0.1 公开 API 提供 `MiddlewareBase.onActing(...)`，其输入
`ActingInput.toolCalls()` 是即将执行的 `ToolUseBlock` 列表，回调 `next` 可接收新的
`ActingInput`。`HarnessAgent.Builder.middleware(MiddlewareBase)` 可以注册该中间件。

因此 `ToolGovernanceInterceptor` 直接实现 AgentScope 中间件，在进入工具执行链前只改写
`review_card_write` 的 `drafts`；无需自建反射、注册表或一套平行拦截框架。

## 已落实的语义

执行方案 2.3 的表格曾写“超配额返回错误”，2.4 与本批次明确验收则要求“只写前 5 张并告警”。
本实现按后者执行：超过上限不是整次失败，而是保留输入顺序截断至 5 张。警告格式为：

```text
review_card_write 单次请求 <原数量> 张复习卡，已截断至 5 张
```

治理只依赖 AgentScope 工具参数的外层契约 `drafts`，不读取或改写单张卡片字段；`review_card_write` 的完整模型契约为
`drafts[{front, back, sourceChunkId}]`。服务端身份、当前 knowledge point 和单一知识库 scope
在工具实现中从已验证的 `RuntimeContext` 绑定，不进入模型参数。

## 接线与测试

`AgentScopeAgentConfiguration` 通过 `HarnessAgent.Builder.middleware(...)` 注册中间件。
`ToolGovernanceInterceptorTest` 覆盖：

1. 10 张草稿只向后传递原顺序的前 5 张，并出现明确警告；
2. 同一批次的其他工具调用保持原对象与参数；
3. 恰好 5 张时不改写、不告警。
