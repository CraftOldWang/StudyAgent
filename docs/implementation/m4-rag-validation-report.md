# RAG 真实 API 验证报告

2026-09-09。已完成固定数据、切块选型、生产检索、父块对照与受控回答评测；这不是完整学习 Agent 验收。

## 固定条件

18份用户课程原件（算法PDF、OS PPTX、编译原理PPTX各六份）；100题中20题开发、80题验证，编译原理不参与选型。验证集包括60道可回答题、20道资料不足题。题目由DeepSeek起草、Codex逐条核对，没有独立人工黄金标注。

六组开发实验后冻结结构切块 child800/overlap0、parent2400/overlap0；jtokkit 1.1.0 CL100K_BASE；qwen3.7-text-embedding/1024维；候选30/30、RRF k=60、Top10、正文预算4096。正式验证使用独立18原件索引，共46父块、137子块，未把测试题或答案放入知识库。选择依据见[切块报告](m4-chunk-selection.md)。

## 检索结果

Hit@5定义为前五个子块包含同一文档哈希对应的完整标注证据；不是全部语义相关答案的召回率。主结果来自320次生产search请求。

| 方法 | 算法 Hit@5 | OS Hit@5 | 编译原理 Hit@5 | 总计 | MRR@10 |
|---|---:|---:|---:|---:|---:|
| BM25 | 8/20 | 17/20 | 17/20 | 42/60，70.0% | 0.6068 |
| VECTOR | 19/20 | 18/20 | 18/20 | 55/60，91.7% | 0.7500 |
| RRF | 18/20 | 19/20 | 18/20 | 55/60，91.7% | 0.7214 |

RRF相对BM25提高21.67个百分点，按课程分层的配对bootstrap区间为[13.33，31.67]个百分点，条件限定于当前语料和标签。问题主要是中文，算法资料多数为英文，这会影响BM25基线。RRF与纯向量Hit@5持平，MRR更低；不能声称全面优于单路检索。

延迟原始数据保留，但这是按固定顺序的一次运行，包含网络/provider波动，不作为速度提升结论。

## 父块回填

独立RRF/PARENT请求有5/80题的排名略有变化，因此另用80次生产服务对照API：每题一次embedding和一次检索，生成两种上下文。80/80验证共享完整子块排名，且两者都受4096正文预算约束。参数及题目未改变，原失败检查与请求均保留，见[测量修正记录](m4-paired-context-evaluation.md)。

| 实际上下文 | 算法证据命中 | OS证据命中 | 编译原理证据命中 | 总计 | 平均正文token |
|---|---:|---:|---:|---:|---:|
| 子块 | 18/20 | 19/20 | 18/20 | 55/60 | 3874.2 |
| 父块 | 14/20 | 20/20 | 20/20 | 54/60 | 3361.7 |

完整证据在全库任一子块中可定位56/60、父块中60/60，但实际回填并不保证更好。大父块受正文预算限制，可能挤掉另一个较低排名但有用的来源；本组中算法退步、另外两门课程改善。父块收益不能写成排名提升或跨课程普遍提升。

## 回答、拒答与评审边界

对80题分别用两种真实上下文回答，再单独调用同型号模型评审，共160次回答、160次评审；使用deepseek-v4-flash，prompt与原始输出均有指纹。该组件测试通过后端eval接口使用相同ObservedModel，不等同于学习Agent的完整多轮流程。

| 自动评审结果 | 子块 | 父块 |
|---|---:|---:|
| 可回答题“正确且有据、引用有效” | 58/60，96.7% | 54/60，90.0% |
| 资料不足题正确拒答 | 20/20 | 19/20 |
| 引用ID超出给定上下文 | 0 | 0 |

**以上是模型评审输出，不能称为人工准确率。** Codex复核全部9条自动拒绝结果，并抽查9条通过结果，发现漏判：临界区的错误结构描述被判正确；Θ定义的参考证据被评审误认成检索上下文；部分解释额外添加不严谨内容。因此不采用“100%有据”“零幻觉”等结论，也不把上述回答率填入简历。

资料不足反例：模型用课件中80386的2.16微秒示例回答当前测试计算机的实际切换耗时。引用确实存在，但回答对象不符。完整审查与一条后续需明确语义范围的黄金题记录见[回答审查](../evidence/m4/answer-review-v1.json)，原始评分未被覆盖。

## 使用与复现

- 适合当前简历的数据：**在60道课程验证问题上，相对BM25，标注证据Hit@5从70.0%提升至91.7%**。面试同时说明与纯向量持平、跨语言材料及小集合的边界。
- 父子切块可表述为支持小块检索、父块回填、来源追踪与预算控制，不能写成本轮已证实的总体质量提升。
- 320次模型调用全部有usage：回答652,888 token，评审699,840 token。本报告采集完成时Goal累计382/2000次模型尝试，最新总数见PROGRESS.md；前期两次失败usage未知，不以零替代。
- `scripts/run-rag-evaluation.py` 复现独立检索；`run-parent-comparison.py` 复现共享排名对照；`evaluate-rag-answers.py` 复现固定回答/评审；`report-rag-evaluation.py` 从原始文件生成[完整JSON报告](../evidence/m4/rag-validation-v1.json)。使用Git提交、JAR、配置、语料、题目、响应、prompt与trace指纹核对版本。
- 本报告关联的后端13项相关回归、Python5项评分/Unicode JSONL/统计回归通过。真实400次验证检索/对照请求、320次模型请求完成。本报告不覆盖M5多轮学习、压缩、上传、Anki和ASR；后续阶段实测状态与证据入口见PROGRESS.md。
